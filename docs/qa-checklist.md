# 온기병동 실기기 QA 체크리스트

> 기준: 2026-11-09, `main` 작업 트리. 코드를 읽고 지금 실제로 있는 기능만 적었어요. 화면 문구는 코드에 있는 그대로예요.
> 오늘이 11월이라 겨울 선물(귤·홍시·호빵)은 실제 서버에서도 놓을 수 있는 때예요.

## 읽는 법

- 한 줄 = 한 항목: `- [ ] 중요도 | 어디서 | 무엇을 하면 → 이렇게 보여야 정상`
- 중요도: **꼭** = 등록 전에 반드시 / *가능하면* = 시간이 되면. **꼭** 항목은 1장, *가능하면* 항목은 2장에 모았어요.
- 어디서: `PC`(PC Chrome) · `아이폰`(아이폰 Safari) · `안드로이드`(안드로이드 Chrome) · `카톡`(카카오톡 인앱 브라우저) · `휴대폰`(아이폰·안드로이드 둘 다) · `전부`(네 곳 모두)
- 기기 두 대가 필요한 항목은 **A**, **B**로 순서를 적었어요. A와 B는 서로 다른 기기(또는 PC의 일반 창 + 시크릿 창)여야 해요. 같은 브라우저의 탭 두 개는 같은 사람이라 예전 탭이 "쉬어요"로 바뀌어요.
- 문제를 찾으면 줄 끝에 `← 기기, 시각, 무엇이 달랐는지`를 적어 두면 다음 대화에서 한꺼번에 고치기 쉬워요.

## 0. 준비

- [ ] **꼭** | PC | 배포 주소 끝에 `?debug=1`을 붙여 열기 → 왼쪽 아래에 작은 글자 상자(id, 병실, 연결, 받음, v5)가 보여요. 붙이지 않으면 아무것도 안 보여요.
- [ ] **꼭** | 전부 | 테스트용 병동을 따로 쓰려면 주소에 `?ward=90`처럼 붙이기 → 상단이 "온기병동 90병동 1호 · n/30"이에요. (E2E 테스트는 97병동을 써요.)
- [ ] **꼭** | 전부 | 시크릿 창을 여러 번 열 때 주의 → 같은 와이파이(같은 IP)에서 **새 게스트는 1시간에 20명까지**예요. 넘으면 "지금은 들어올 수 없어요 / 잠시 뒤에 다시 와 주세요."가 떠요. 이건 정상이에요. 테스트가 막히면 휴대폰 데이터로 바꾸거나 1시간 기다려요.

디버그 표시 읽는 법:

| 줄 | 뜻 |
| --- | --- |
| `id ab12cd34` | 이번 접속의 공개 번호(publicId). 다시 접속하면 바뀌어요 |
| `병실 1병동 1번` | 병동 번호와 인스턴스 번호. 30명이 차면 2번, 3번으로 넘어가요 |
| `연결 online` | connecting / online / reconnecting / offline / paused / replaced / full / outdated / blocked / limited |
| `받음 event:walk (37)` | 마지막으로 받은 메시지 종류와 지금까지 받은 개수 |
| `v5` | 화면의 프로토콜 버전 |

화면 연출만 바꾸는 주소 옵션(서버 판단에는 영향이 없어요):

| 옵션 | 보이는 것 | 바뀌지 않는 것 |
| --- | --- | --- |
| `?time=morning` | 낮 조명 + 여섯 병실 창문이 모두 열림 | "좋은 아침이에요" 한마디는 실제 06:30~09:00에만 보여요 |
| `?time=day` / `evening` / `night` | 그 시간대 조명 | 소등 안내, 함께한 밤 |
| `?clockShift=분` | 화면 시계를 그만큼 옮겨서 소등 안내·함께한 밤까지 미리 보기 | 서버 시계, 아침 한마디, 겨울 선물 |
| `?season=winter` / `spring` / `summer` / `autumn` | winter면 눈·김·겨울 간식이 보이고, 나머지는 숨겨요. 붙이지 않으면 지금처럼 일 년 내내 보여요 | 겨울 선물 버튼과 서버 검사는 실제 날짜를 따라요 |

## 1. 꼭 해야 하는 것

### 1-0. PC와 휴대폰 두 기기로 한 바퀴 (가장 먼저)

A = PC Chrome, B = 휴대폰. 두 기기 모두 같은 주소에 `?ward=90&debug=1`을 붙여 열어요. localhost와 배포 주소, preview와 production을 섞으면 서로 다른 병동이라 보이지 않아요.

- [ ] **꼭** | A·B | 둘 다 입장 → 상단이 둘 다 "온기병동 90병동 1호 · 2/30"이고, 디버그 `연결 online`, `병실 90병동 1번`이 같아요. 한쪽이 "혼자 머무는 중"이거나 `connecting`에 8초 넘게 머물면 기록해 두기(서버 비밀값·주소를 확인해요).
- [ ] **꼭** | A·B | **서로 보이기** → A 화면에 B 동물과 닉네임이, B 화면에 A 동물과 닉네임이 보여요.
- [ ] **꼭** | A·B | **걷기**: A가 병실 바닥을 누르기 → B 화면에서 A가 그곳으로 걸어가요(디버그 `받음 event:walk`). B도 걸어서 A 화면에서 확인해요.
- [ ] **꼭** | A·B | **눕기**: A가 빈 침대를 누르기 → B 화면에서 A가 그 침대에 누워요(`event:lie`). B가 같은 침대를 누르면 "다른 분이 먼저 자리를 잡았어요."
- [ ] **꼭** | A·B | **선물 5종**: A가 [머리맡 선물] → 네잎클로버·오잎클로버·귤·홍시·호빵을 B가 누운 침대(또는 빈 침대)에 하나씩 → 다섯 번 모두 B 화면 협탁에 같은 선물이 놓여요(`event:gift`). B를 새로고침해도 협탁에 그대로 있어요.
- [ ] **꼭** | A·B | **불빛**: A가 병실 안이나 침대에서 [창가에 불빛] → A 화면에 빛이 창틀로 날아가고 "창가에 불빛을 놓았어요. 오늘 이 병실에 n개예요."가 떠요. B 화면 같은 병실 창틀에 램프가 하나 늘어요(`event:lamp`). B를 새로고침해도 그대로예요.
- [ ] **꼭** | A·B | **안아 주기**: 2m 안에서 A가 B를 누르기 → 메뉴에 [안아 주기]가 있어요. 멀면 버튼이 꺼지고 "조금 더 가까이 다가가 주세요."가 보여요. B에게 [안길게요]/[다음에요]가 뜨고, 10초 두면 조용히 사라져요.
- [ ] **꼭** | A·B | **나갔다 다시 들어오기**: B가 창을 닫고 1분 기다리기 → A 화면에서 B가 사라지고 인원이 1/30이 돼요. A가 [평안 빌기] → [자리에 없는 분께 남기기] → B → "남겨두었어요. 다음에 들어오시면 전해져요." 한 번 더 하면 "그분께는 오늘 이미 남겼어요." B가 다시 열기 → "돌아왔네요, ○○님" → [이대로 들어갈게요] → "내가 없는 동안 도착한 평안"에 A의 평안이 보여요. 다시 새로고침하면 뜨지 않아요. A 화면에 B가 다시 보여요.
- [ ] **꼭** | B | 30초 안에 다시 들어오기(휴대폰 화면을 잠깐 껐다 켜기) → 같은 침대와 자리 그대로예요. A 화면에서 B가 사라지지 않았어요.

### 1-1. 처음 입장과 다시 입장

- [ ] **꼭** | 전부 | 시크릿 창(카톡은 처음 여는 링크)으로 주소 열기 → "병동을 여는 중" 다음에 "어떤 모습으로 머물까요?" 입장 화면이 떠요. 닉네임 칸에 "따뜻한 곰"처럼 자동 닉네임이 채워져 있어요.
- [ ] **꼭** | 전부 | 입장 화면에서 동물 그림 다섯 개를 하나씩 누르기 → 뒤의 3D 동물이 바로 바뀌고, 자동 닉네임의 동물 이름도 함께 바뀌어요.
- [ ] **꼭** | 전부 | [환자]/[문병객], [함께 갈게요]/[혼자 갈게요]를 바꿔 보기 → 옷과 고양이가 바로 바뀌어요.
- [ ] **꼭** | 전부 | 입장 화면 맨 아래에 "의료 서비스가 아니에요" 안내가 **없어요**(지웠어요).
- [ ] **꼭** | 전부 | [병동에 들어갈게요] → 입장 화면이 사라지고 상단에 "온기병동 1병동 1호 · 1/30"과 "오늘 다녀간 동물 n마리 · 모인 평안 n"이 보여요. 아래쪽에 동작 버튼, 오른쪽 위에 [설정]이 있어요.
- [ ] **꼭** | 전부 | 들어간 뒤 새로고침 → 입장 화면 제목이 "돌아왔네요, ○○님"이고 버튼이 [이대로 들어갈게요]예요. 같은 동물·옷·닉네임이 골라져 있어요. 들어가면 서버가 같은 사람으로 알아봐요(디버그 `받음`에 `guest-token`이 다시 오지 않아요).
- [ ] **꼭** | 카톡 | 저장소를 쓸 수 없는 브라우저면 "이 브라우저는 다음 방문을 기억하지 못해요. 다시 오시면 새로 만나요."가 한 번 떠요.
- [ ] **꼭** | 아이폰, 안드로이드 | 닉네임 칸을 누르기 → 키보드가 올라와도 화면이 확대되지 않고, 입력 칸이 키보드에 가리지 않아요.
- [ ] **꼭** | 아이폰 | 노치·홈 바가 있는 기기에서 세로/가로 돌려 보기 → 버튼과 글자가 노치나 홈 바에 가리지 않아요.
- [ ] **꼭** | 카톡 | 카톡 채팅방에 주소를 보내고 눌러 열기 → 입장 화면이 뜨고 들어갈 수 있어요. 카톡을 완전히 닫았다가 같은 링크를 다시 열면 같은 닉네임이 채워져 있어요(지워져 있으면 카톡이 저장소를 지운 것이라 기록해 두기).

- [ ] **꼭** | 전부 | 앞마당에서 현관으로 들어서기 → 간호사실 가운데 병아리 간호사가 고개를 숙이며 "어서 오세요. 편히 쉬다 가세요" 말풍선을 띄워요. 밖에 나갔다 다시 들어오면 "다시 오셨네요". 움직임 줄이기에서는 숙이지 않고 말풍선만 떠요.
- [ ] **꼭** | 전부 | [함께 갈게요]로 들어와 걷기 → 고양이가 뒤가 아니라 옆에서 나란히 걸어요. 멈추면 옆에 앉고, 누우면 침대 옆에 웅크려요. 병동 고양이는 통통하고 둥근 몸에 짧은 다리, 목에 방울이에요.

### 1-2. 닉네임 경계값

입력하는 즉시 칸 아래에 안내가 뜨고, 맞지 않으면 [병동에 들어갈게요]가 눌리지 않아야 해요.

- [ ] **꼭** | 전부 | `곰` (1자) → "닉네임은 2자 이상으로 지어 주세요." 버튼이 흐려요.
- [ ] **꼭** | 전부 | `곰곰` (2자) → 안내 없이 들어갈 수 있어요.
- [ ] **꼭** | 전부 | `가나다라마바사아자차` (10자) → 들어갈 수 있어요. 다른 기기 화면의 머리 위 이름이 잘리거나 겹치지 않아요.
- [ ] **꼭** | 전부 | `가나다라마바사아자차카` (11자) → "닉네임은 10자까지 쓸 수 있어요."
- [ ] **꼭** | 전부 | `  곰  ` (앞뒤 공백) → 공백을 빼고 "곰"으로 보아서 2자 미만 안내가 떠요.
- [ ] **꼭** | 전부 | `1234곰` → "숫자는 4개 넘게 이어서 쓸 수 없어요."
- [ ] **꼭** | 전부 | `010-1234-5678` (13자) → 길이 안내("10자까지")가 먼저 떠요. `1234-5678`은 숫자 안내가 떠요.
- [ ] **꼭** | 전부 | `010 123 45`처럼 숫자를 3개 이하로 끊어 쓰기 → **지금 코드는 통과시켜요.** 받아들여도 되는지 판단해서 적어 두기.
- [ ] **꼭** | 전부 | `a.com`, `www곰`, `곰닷컴`, `http:곰` → "주소처럼 보이는 글자는 쓸 수 없어요."
- [ ] **꼭** | 전부 | `곰@곰` → "이메일처럼 보이는 글자는 쓸 수 없어요."
- [ ] **꼭** | 전부 | `shared/bannedWords.ts`의 단어 하나를 그대로, 그리고 사이에 띄어쓰기·점을 끼워서 → 둘 다 "다른 닉네임으로 지어 주세요."
- [ ] **꼭** | 전부 | 이모지 닉네임 `🐻🐻` → 들어갈 수 있고, 다른 기기 머리 위에도 깨지지 않고 보여요.
- [ ] **꼭** | PC | `<b>곰</b>` 입력 → 거절되거나, 들어가도 머리 위에 글자 그대로 `<b>곰</b>`이 보여요(굵게 바뀌면 안 돼요).

### 1-3. 이동과 침대

- [ ] **꼭** | 전부 | 바닥을 한 번 누르기 → 그곳으로 걸어가요. 벽 너머나 건물 밖을 누르면 갈 수 있는 가까운 곳에서 멈춰요.
- [ ] **꼭** | 휴대폰 | 한 손가락으로 끌기, 두 손가락으로 벌리기/오므리기 → 화면이 돌고 확대·축소돼요. 끈 뒤 손을 떼도 그 자리로 걸어가지 않아요.
- [ ] **꼭** | 전부 | 빈 침대 누르기 → 걸어가서 누워요. 바닥을 누르면 일어나요. 누운 동안 [잠들기], [내 침대] 버튼이 보여요.
- [ ] **꼭** | 전부 | A, B 두 기기로 같은 병동에 들어가기 → A: B가 들어오는 모습과 머리 위 닉네임이 보여요. 상단 숫자가 2/30이 돼요. B: 같아요.
- [ ] **꼭** | 전부 | A가 걸어 다니기 → B 화면에서 A가 같은 곳으로 걸어가요(조금 늦어도 괜찮아요).
- [ ] **꼭** | 전부 | A가 침대에 눕기 → B 화면에서 A가 그 침대에 누워 있어요. B가 같은 침대를 누르면 "다른 분이 먼저 자리를 잡았어요."
- [ ] **꼭** | A·B | **침대 이름표**: A가 침대에 눕기 → A·B 화면 모두 그 침대 발치에 A의 닉네임 이름표가 달려요. A가 일어나거나 나가면 B 화면에서 사라져요.
- [ ] **꼭** | A·B | **침대 옮기기**: A가 누운 채 다른 빈 침대 누르기 → "이 침대로 옮길까요?" → [그대로 있을게요]면 그대로 누워 있어요. [옮길게요]면 걸어가 새 침대에 눕고, B 화면에서 이름표가 새 침대로 옮겨져요. 원래 침대는 바로 B가 누울 수 있어요.
- [ ] **꼭** | A·B | **옮기기 경쟁**: A가 "이 침대로 옮길까요?"를 띄운 채, B가 그 침대에 먼저 눕기 → A가 [옮길게요] → "방금 다른 분이 누우셨어요."가 뜨고 A는 원래 침대에 그대로 있어요.
- [ ] **꼭** | 휴대폰 | **같은 침대 동시 누르기**: A와 B가 셋을 세고 같은 빈 침대를 동시에 누르기 → 한 사람만 눕고, 다른 사람은 "다른 분이 먼저 자리를 잡았어요."가 떠요. 두 화면 모두 누운 사람이 같아요. 3번 반복하기.
- [ ] **꼭** | 전부 | A가 창을 닫기 → 약 30초 뒤 B 화면에서 A가 사라지고 상단 숫자가 줄어요.

### 1-4. 평안을 빌어 주는 동작 (두 기기)

- [ ] **꼭** | 전부 | A: [평안 빌기] → [침대 고르기] → 빈 침대 → A가 손을 모으고 빛이 그 침대 머리맡으로 날아가요. B: 같은 빛이 보이고 상단 "모인 평안" 숫자가 1 늘어요.
- [ ] **꼭** | 전부 | A: [평안 빌기] → [자리에 없는 분께 남기기] → B 이름("○○ (함께 있어요)") → A: 빛이 B 머리 위로 가요. B: 자기 머리 위로 빛이 와요(디버그 `받음`에 `event:bless`).
- [ ] **꼭** | 전부 | A: [목례와 한마디] → "평안하시길" 등 다섯 가지를 하나씩 → A가 고개를 숙이고 말풍선이 떠요. B 화면에서도 A 머리 위에 같은 말이 떠요. "괜찮아요?"·"힘내요" 같은 말은 어디에도 없어요.
- [ ] **꼭** | 전부 | A: [머리맡 선물] → 네잎클로버 → B가 누운 침대 → A와 B 화면 모두 그 침대 협탁에 네잎클로버가 놓여요.
- [ ] **꼭** | 전부 | 11월~2월에 [머리맡 선물] → 귤·홍시·호빵이 흐리지 않고 놓을 수 있어요.
- [ ] **꼭** | 전부 | 오잎클로버를 두 번 놓기 → 두 번째는 "오잎클로버는 내일 다시 놓을 수 있어요."
- [ ] **꼭** | 전부 | 선물을 11개째 놓기(오잎 제외) → "오늘은 선물을 넉넉히 놓았어요. 내일 또 놓아 주세요."
- [ ] **꼭** | 전부 | 병실 안에서 [창가에 불빛] → A 화면에 "창가에 불빛을 놓았어요. 오늘 이 병실에 n개예요."가 뜨고, A·B 화면 모두 그 병실 창가 불빛이 하나 늘어요. 복도에서 누르면 "병실에 들어가면 놓을 수 있어요."
- [ ] **꼭** | 휴대폰 | **포옹**: A와 B를 2m 안으로 가까이 → A: B를 누르고 [안아 주기] → B: "안아 주기" 요청과 [안길게요]/[다음에요]가 떠요 → B가 [안길게요] → A가 다가가 안고 두 화면 모두 따뜻한 빛이 보여요.
- [ ] **꼭** | 휴대폰 | 포옹을 [다음에요]로 거절 → A에게 거절 안내가 떠요. 10분 안에 같은 사람에게 다시 청하면 거절 안내(too-soon)가 떠요.
- [ ] **꼭** | 휴대폰 | 멀리 떨어져서 다른 동물 누르기 → [안아 주기]가 꺼져 있고 "조금 더 가까이 다가가 주세요."가 보여요. B가 수면 모드이거나 [설정]에서 '받지 않기'면 "지금은 쉬고 있어요. 다음에 안아 주세요."예요.
- [ ] **꼭** | 휴대폰 | B가 누워 있을 때 포옹 → A가 침대 곁으로 가서 안아요.

### 1-5. 남겨진 평안과 내가 없는 동안 도착한 평안

- [ ] **꼭** | 전부 | A: 빈 침대에 [평안 빌기]와 [머리맡 선물] → B(다른 기기): 그 침대에 눕기 → 다 누우면 "○○님이 남긴 평안" 카드가 떠요. [닫기]로 닫혀요. 그 침대에 다시 누우면 카드가 다시 뜨지 않아요.
- [ ] **꼭** | 전부 | A와 B가 같은 병실에서 만난 뒤 B가 창을 닫고 1분 기다리기 → A: [평안 빌기] → [자리에 없는 분께 남기기] → B 이름("함께 있어요"가 없음) → "남겨두었어요. 다음에 들어오시면 전해져요."
- [ ] **꼭** | 전부 | 위에 이어서 A가 B에게 한 번 더 남기기 → "그분께는 오늘 이미 남겼어요. 내일 또 남겨 주세요."
- [ ] **꼭** | 전부 | B가 다시 들어오기 → 들어가자마자 A가 남긴 평안 카드가 먼저 보여요. 한 번 더 새로고침하면 다시 뜨지 않아요.

### 1-6. 방명록(사과나무)과 문병 (두 기기, 카톡)

- [ ] **꼭** | 휴대폰 | A: 침대에 누워 [내 침대] → [내 사과나무] → 방명록 화면이 열려요. [링크 만들기] → 링크 주소(`/guestbook/…`) 전체가 보이고, [복사]를 누르면 "복사했어요", [보내기]는 공유 창(안 되면 복사)이에요. 아래에 "이 링크를 받은 분만 사과를 남길 수 있어요".
- [ ] **꼭** | 카톡 | A가 링크를 카톡으로 B에게 보내기 → 카톡 미리보기에 A의 닉네임이나 병실이 드러나지 않아요(정적인 제목만). B: 링크 누르기 → 3D 없이 "온기병동 방명록 / ○○님의 사과나무 / 지금까지 사과 n개가 열렸어요"와 나무가 보여요. 주소창은 `/guestbook`이에요.
- [ ] **꼭** | 휴대폰 | B: [사과 하나 달아 주기] → 이름·한마디·짧은 글 → [사과 달기] → 시트가 닫히고 봉오리가 사과로 열린 뒤 카드가 잠깐 떠요. 개수가 하나 늘어요.
- [ ] **꼭** | 휴대폰 | B: 짧은 글에 주소(`www.…`)나 금칙어를 넣기 → 안내가 뜨고 달리지 않아요. 이름 1자도 마찬가지예요.
- [ ] **꼭** | 휴대폰 | C(다른 기기)도 같은 링크로 사과 달기 → B 화면을 새로고침하면 C의 사과는 모양만 보이고 눌리지 않아요. B의 사과만 눌러서 내용을 볼 수 있어요.
- [ ] **꼭** | 휴대폰 | A: [내 사과나무] → 모든 사과를 눌러 이름·날짜·한마디·짧은 글을 봐요. 카드 밖을 누르면 닫혀요. [이 사과 숨기기] → 바로 사라져요.
- [ ] **꼭** | 휴대폰 | A가 누워 있는 동안 **A 화면에만** 침대 발치 옆에 작은 사과나무가 보여요. B·C가 병실에 들어와도 그 자리에 나무가 없어요.
- [ ] **꼭** | 카톡 | B: 방명록 화면 맨 아래 [병실에 문병 가기 →] → "○○님에게 문병 왔어요", 옷 고르기가 없고 [문병 갈게요] → A의 침대 곁에서 시작하고 "○○님 곁에 왔어요."가 떠요. A 화면: "○○님이 문병 왔어요". B에게는 [내 침대]가 없고, 병실 어디서도 다른 분의 사과나무를 열 수 없어요.
- [ ] **꼭** | 휴대폰 | A가 나간 뒤 B가 문병 가서 A 침대에 평안 빌기 → B: "○○님은 지금 자리에 없어요. 남긴 평안과 선물은 돌아오시면 전해져요." A가 다시 들어오면 카드가 와요.
- [ ] **꼭** | 휴대폰 | A: [링크 끄기] → B가 링크 열기 → "이 방명록 링크는 더 이상 열리지 않아요." [새 링크 만들기] 뒤에도 예전 링크는 닫혀 있고, 새 링크는 열려요.
- [ ] **꼭** | 휴대폰 | 같은 링크로 1시간에 사과 11개째 → "이 링크로는 사과가 많이 열렸어요. 한 시간 뒤에 다시 달아 주세요."

### 1-7. 재접속

- [ ] **꼭** | 휴대폰 | 침대에 누운 채 와이파이 끄기 → "연결이 잠시 끊겼어요. 다시 이어지는 중이에요." 띠가 떠요(디버그 `reconnecting`).
- [ ] **꼭** | 휴대폰 | 위에서 **30초 안에** 와이파이 켜기 → 띠가 사라지고 같은 침대에 그대로 누워 있어요. B 화면에서 A가 나갔다 들어오지 않아요.
- [ ] **꼭** | 휴대폰 | 와이파이를 **1분 넘게** 껐다 켜기 → 다시 이어져요. B 화면에서는 A가 나갔다가 새로 들어와요. 그사이 B가 A 침대에 누웠으면 A에게 "다시 이어지는 사이 다른 분이 침대에 누웠어요."
- [ ] **꼭** | 휴대폰 | 와이파이 → 휴대폰 데이터로 바꾸기(IP가 바뀌어요) → 끊겼다 다시 이어지고 같은 사람으로 돌아와요.
- [ ] **꼭** | 휴대폰 | 다른 앱으로 1분 갔다가 돌아오기, 화면을 잠갔다 풀기 → 다시 이어지고 병실이 그대로예요. 멈춘 채 "병동을 여는 중"으로 돌아가지 않아요.

### 1-8. 수면 모드와 소리

- [ ] **꼭** | 휴대폰 | 침대에 누워 [잠들기] → 화면이 아주 어두워지고 바람 소리가 아주 작게 들려요. 3초쯤에 걸쳐 천천히 커져요.
- [ ] **꼭** | 휴대폰 | **수면 모드 5분 유지**(휴대폰을 내려놓고 아무것도 누르지 않기) → 5분 동안 화면이 꺼지지 않고, 소리가 끊기지 않고, "잠들었어요" 화면으로 바뀌지 않아요(디버그 `online` 유지).
- [ ] **꼭** | 휴대폰 | 위 5분 동안 B가 A를 눌러 보기 → B에게 [안아 주기]가 없거나 받을 수 없다는 안내가 떠요. A에게 요청이 오지 않아요.
- [ ] **꼭** | 휴대폰 | 5분 뒤 [깨어나기] → 소리가 천천히 사라지고 화면이 밝아져요. 여전히 같은 침대에 누워 있어요.
- [ ] **꼭** | 아이폰 | 소리 확인 → 소리는 [잠들기]를 누른 **뒤에만** 나요. 들어가자마자 저절로 소리가 나면 안 돼요. 무음 스위치를 켜면 안 들릴 수 있어요(기록만).
- [ ] **꼭** | 안드로이드, 카톡 | [잠들기] 뒤 소리가 들리는지, 볼륨 버튼으로 크기가 바뀌는지 → 들리고 바뀌어요.
- [ ] **꼭** | 휴대폰 | 수면 모드에서 다른 앱 갔다 오기 → 돌아오면 다시 화면이 꺼지지 않게 돼요(화면 꺼짐 시간 30초로 맞추고 확인).

### 1-9. 시간대와 계절

- [ ] **꼭** | 전부 | `?time=morning` / `day` / `evening` / `night` 하나씩 → 조명이 바뀌어요. morning은 낮 조명에 창문이 모두 열려 있어요. night에는 천장 불이 꺼지고 작은 수면등만 켜져요.
- [ ] **꼭** | 전부 | `?time=morning`으로 [목례와 한마디] (실제 시각이 아침이 아닐 때) → "좋은 아침이에요"가 **없어요**(서버 판단은 그대로).
- [ ] **꼭** | 전부 | `?season=spring` → 눈·김·협탁 간식이 사라져요. `?season=winter` → 다시 보여요. 두 경우 모두 [머리맡 선물]의 귤·홍시·호빵은 실제 날짜(11월이면 놓을 수 있음)를 따라요.
- [ ] **꼭** | 전부 | 실제 **밤**(22시 넘어서) 들어가기 → 소등 조명이고, 들어가면 "소등 시간이에요. 오늘 밤 함께 잠드는 분 n명" 안내가 떠요.
- [ ] **꼭** | 전부 | 실제 21:59에 병실에 있다가 22:00 넘기기(또는 `?clockShift`로 1분 전에 맞추기) → 조명이 천천히 바뀌고 소등 안내가 한 번 떠요.
- [ ] **꼭** | 전부 | 실제 **아침**(06:30~09:00) 그날 처음 병실에 들어가기 → 그 병실 창문이 열려요. B 화면에서도 열려 있어요. [목례와 한마디]에 "좋은 아침이에요"가 있어요.
- [ ] **꼭** | 전부 | 09:00이 지나면 → 열린 창문이 조용히 닫히고 "좋은 아침이에요"가 사라져요.
- [ ] **꼭** | PC | 기기 시간대를 미국으로 바꾸고 열기 → 조명과 소등은 여전히 한국 시간을 따라요.

### 1-10. 느린 인터넷, 발열, 버벅임

- [ ] **꼭** | PC | 개발자도구 → Network → 위쪽 'No throttling'을 **Slow 4G**로 → 새로고침 → "병동을 여는 중"이 먼저 보이고, 30초 안에 입장 화면이 떠요. 들어간 뒤 걷기·평안 빌기가 늦게라도 한 번씩만 일어나요(두 번 일어나면 안 돼요). 처음 뜨기까지 걸린 초를 적기.
- [ ] **꼭** | PC | Slow 4G에서 같은 침대를 A와 동시에 누르기 → 여전히 한 사람만 누워요.
- [ ] **꼭** | PC | Network → **Offline**으로 10초 → 끊김 띠가 떴다가, 다시 'No throttling'으로 돌리면 사라져요.
- [ ] **꼭** | 휴대폰 | 10분 동안 걷고 동작하기 → 손에 쥐기 불편할 만큼 뜨거워지지 않아요. 시작·끝 배터리 %를 적기.
- [ ] **꼭** | 휴대폰 | 화면을 돌리고 걷는 동안 → 눈에 띄게 끊기거나 멈추지 않아요. 오래된 기기(3~4년 전 기종)가 있으면 그 기기로도.
- [ ] **꼭** | 휴대폰 | 수면 모드 10분 → 걸을 때보다 덜 뜨거워요(수면 모드는 초당 4번만 그려요).
- [ ] **꼭** | 휴대폰 | 30분 넘게 켜 두기 → 앱이 저절로 새로고침되거나 하얗게 되지 않아요(아이폰은 메모리가 모자라면 탭을 다시 불러요. 일어나면 기록).

### 1-11. 길게 누르기

**인형 기능은 지금 코드에 없어요.** 그래서 길게 누르기에 반응하는 기능은 없고, 브라우저 기본 메뉴가 끼어들지 않는지만 봐요.

- [ ] **꼭** | 아이폰, 카톡 | 3D 화면(바닥·침대·다른 동물)을 1초 넘게 누르기 → 글자 선택, 확대경, "이미지 저장" 메뉴가 뜨지 않아요. 손을 떼도 걸어가지 않아요.
- [ ] **꼭** | 안드로이드 | 3D 화면과 버튼을 길게 누르기 → 복사·검색 메뉴나 진동 메뉴가 뜨지 않아요.
- [ ] **꼭** | 휴대폰 | 동작 버튼과 머리 위 닉네임을 길게 누르기 → 글자가 선택되지 않아요.
- [ ] **꼭** | 휴대폰 | 닉네임 칸은 길게 누르기 → 이곳만은 붙여넣기 메뉴가 떠야 정상이에요.

### 1-12. 안전

- [ ] **꼭** | PC | **토큰 조작**: 개발자도구 → Application → Local Storage → 주소 선택 → `onward.token` 값의 **가운데쯤** 글자 하나를 다른 영문자로 바꾸기(마지막 글자는 바꿔도 같은 값으로 읽힐 때가 있어서 피해요. 7장 참고) → 새로고침 → 들어가기 → Network → WS 메시지에 `guest-token`이 새로 와요(새 게스트). 예전 사람에게 남긴 평안은 오지 않아요. 오류 화면이 나지 않아요.
- [ ] **꼭** | PC | `onward.token`을 `abc`처럼 모양이 틀린 값으로 바꾸기 → 위와 같이 새 게스트로 들어가요.
- [ ] **꼭** | PC | **guestId가 남에게 가지 않는지**: 아래 3장 방법으로 B의 WS 메시지를 열고 검색 → `guestId`는 0건이에요. 다른 사람은 8자 `id`로만 나와요. `"token"`은 B 자신의 `guest-token`과, B가 방명록 링크를 만든 순간의 `guestbook` 말고는 없어요. 다른 사람의 WS 메시지에서 `apple`·`guestbook`·`tree`를 검색해도 0건이에요.
- [ ] **꼭** | PC | WS 메시지에서 A의 `snapshot`을 열어 `guests` 확인 → 사람마다 `id, animal, outfit, nickname, withCat, x, z, bed, address, hugOk`만 있어요. IP, 해시, 나이·건강 같은 칸은 없어요.
- [ ] **꼭** | 휴대폰 | **신고**: A가 B를 누르고 [신고하기] → 사유 고르기 → "신고를 받았어요. 운영자가 살펴볼게요." 같은 B를 다시 신고하면 "이미 신고하신 분이에요. 운영자가 살펴볼게요."
- [ ] **꼭** | PC | 신고 뒤 운영자 API로 신고 목록 보기(4장) → 방금 신고가 B의 신고 당시 닉네임·사유·병실과 함께 보여요. `targetHash`는 64자 해시이고 원래 guestId나 IP는 없어요.
- [ ] **꼭** | PC | 운영자 API: 키 없이, 틀린 키로 부르기 → `401 {"v":6,"error":"unauthorized"}`. 맞는 키로 → `200`.
- [ ] **꼭** | PC | 운영자 API `block`으로 B를 막기 → B가 지금 병실에 있으면 바로 나가고 "지금은 들어올 수 없어요"가 떠요. 새로고침해도 같아요. (**풀어 주는 API가 없어서 30일 동안 풀 수 없어요.** 테스트용 시크릿 창 게스트에게만 하기.)
- [ ] **꼭** | 휴대폰 | [설정] 아래쪽 → "마음이 많이 힘들 때는 109(자살예방상담전화, 24시간)에 전화해 주세요."와 [109에 전화하기] → 누르면 전화 앱에 109가 채워져요(걸지 않고 취소).
- [ ] **꼭** | 카톡 | 카톡 인앱에서 [109에 전화하기] → 전화 앱이 열려요(아무 일도 없으면 기록).
- [ ] **꼭** | 전부 | [설정]에 [개인정보 처리방침] 링크가 없어요(잠시 내려 두었어요). `/privacy`를 열면 병동 화면으로 가요.
- [ ] **꼭** | 전부 | [설정] → [만든 사람과 출처] → `/credits`가 새 탭으로 열리고, `[만든 사람]` 자리 표시가 실제 이름으로 바뀌어 있어요.
- [ ] **꼭** | 휴대폰 | `?debug=1`로 들어가 5초 뒤 왼쪽 아래에 `품질 normal · NNfps` 또는 `품질 light · NNfps`가 보여요. 오래된 휴대폰이면 light예요.
- [ ] **꼭** | 전부 | [설정] → [가볍게 보기] → [켜기]를 누르면 바로 화면이 조금 거칠어지고 눈이 줄어요. [끄기]로 돌아와요. 새로고침해도 고른 값이 남아요.
- [ ] 전부 | 다른 탭으로 갔다가 돌아오면 동물이 순간이동하지 않고 이어서 움직여요.
- [ ] 전부 | 개발자 도구 콘솔에서 `document.querySelector('#scene').getContext('webgl2').getExtension('WEBGL_lose_context').loseContext()` → "이 기기에서는 병실을 보여주기 어려워요"와 [다시 시도]가 떠요.

- [ ] 서버 | `POST /api/stats`는 405, `OPTIONS /api/stats`는 204예요.
- [ ] **꼭** | 전부 | 처리방침의 "문의" → **지금은 `[문의 이메일]` 자리 표시 그대로예요.** 등록 전에 채워야 해요.

## 3. 참고: WebSocket 메시지 보는 법

**PC Chrome**

1. 병동 주소를 열고 F12(맥은 ⌥⌘I)로 개발자도구를 열어요.
2. **Network** 탭 → 필터 줄에서 **WS**를 눌러요.
3. 새로고침하고 들어가요. 목록에 `ws?ward=1&instance=1`이 생겨요. 눌러요.
4. 오른쪽 **Messages** 탭: ↑(초록)은 내가 보낸 것, ↓(빨강)은 받은 것이에요.
5. 메시지 목록 위 **Filter** 칸에 `guestId`를 입력 → 아무것도 남지 않아야 해요. `token`도 넣어 보고, 남는 줄이 `guest-token`·`guestbook`(내가 링크를 만든 순간)뿐인지 봐요.
6. 줄을 누르면 아래에 전체 JSON이 보여요. `snapshot`의 `guests`를 펼쳐 칸 이름을 확인해요.

**안드로이드 Chrome**: 휴대폰 설정 → 개발자 옵션 → USB 디버깅을 켜고 PC와 USB로 이어요 → PC Chrome 주소창에 `chrome://inspect` → 휴대폰의 탭 아래 **inspect** → 위와 같아요.

**아이폰 Safari**: 아이폰 설정 → Safari → 고급 → 웹 속성 켜기 → 맥과 USB로 잇기 → 맥 Safari 메뉴 **개발자용** → 아이폰 이름 → 병동 탭 → **네트워크** 탭에서 `ws?ward=` 항목을 눌러 메시지를 봐요.

**카톡 인앱 브라우저**: 메시지를 볼 방법이 마땅치 않아요. 안전 항목은 PC에서 확인하고, 카톡에서는 화면 동작만 봐요.

## 4. 참고: 운영자 API curl 예시

README와 같아요. 키가 터미널 기록에 남지 않게 환경 변수로 넣어요.

```sh
export ONWARD=https://<배포 주소>        # 개발이면 http://localhost:5173
read -rs ADMIN_KEY && export ADMIN_KEY  # 화면에 보이지 않게 키 입력 후 엔터

# 최근 신고 보기 → reports[].targetHash 를 아래 명령에 써요
curl -s "$ONWARD/admin/reports?limit=50" -H "Authorization: Bearer $ADMIN_KEY"

# 키가 틀리면 401
curl -s -o /dev/null -w "%{http_code}\n" "$ONWARD/admin/reports" -H "Authorization: Bearer wrong"

# 입장 막기 (테스트용 게스트에게만! 30일 동안 풀 수 없어요)
curl -s -X POST "$ONWARD/admin/block" \
  -H "Authorization: Bearer $ADMIN_KEY" -H "Content-Type: application/json" \
  -d '{"v":6,"guestHash":"<64자 해시>","reason":"QA 차단 확인"}'

# 닉네임 되돌리기 / 가림 풀기 (신고된 적이 있는 사람만) / 방명록 링크 끄기
curl -s -X POST "$ONWARD/admin/reset-nickname" \
  -H "Authorization: Bearer $ADMIN_KEY" -H "Content-Type: application/json" \
  -d '{"v":6,"guestHash":"<64자 해시>","reason":"QA 닉네임 되돌리기"}'
curl -s -X POST "$ONWARD/admin/clear-flag" \
  -H "Authorization: Bearer $ADMIN_KEY" -H "Content-Type: application/json" \
  -d '{"v":6,"guestHash":"<64자 해시>","reason":"QA 가림 풀기"}'
curl -s -X POST "$ONWARD/admin/revoke-guestbook-link" \
  -H "Authorization: Bearer $ADMIN_KEY" -H "Content-Type: application/json" \
  -d '{"v":6,"guestHash":"<64자 해시>","reason":"QA 링크 끄기"}'
```

정상 답: `200 {"v":6,"ok":true,"affected":n}`. 본문이 틀리면 `400`, 없는 사람이면 `404 unknown_guest`, 키를 계속 틀리면 `429`.

## 5. 참고: Cloudflare 대시보드에서 볼 곳

메뉴 이름은 대시보드 개편에 따라 조금 다를 수 있어요.

| 어디 | 무엇을 적나 |
| --- | --- |
| **Workers & Pages → onward → Metrics** (또는 Observability) | 요청 수, 오류 수, CPU 시간 |
| **Workers & Pages → Durable Objects** (또는 onward → Durable Objects 탭) → `WardRoom`, `Directory` | 요청 수, Duration(GB-s), WebSocket 메시지 수, 저장 용량, SQLite 읽은 행·쓴 행 |
| 계정 홈 → **Usage** / Billing의 사용량 | 오늘 쓴 양을 무료 한도와 견준 % |

무료 플랜 한도(하루 기준, 등록 전에 Cloudflare 가격 페이지에서 한 번 더 확인해 주세요):

| 항목 | 무료 한도 |
| --- | --- |
| Worker 요청 | 100,000 / 일 |
| Durable Objects 요청 | 100,000 / 일 (받은 WebSocket 메시지 20개 = 요청 1개로 셈) |
| Durable Objects Duration | 13,000 GB-s / 일 |
| SQLite 읽은 행 | 5,000,000 / 일 |
| SQLite 쓴 행 | 100,000 / 일 |
| SQLite 저장 | 5 GB (전체) |

테스트 뒤 적어 둘 숫자: 30분 두 기기 테스트 동안 늘어난 **DO 요청 수**, **Duration**, **쓴 행**. 이 셋 가운데 한도 대비 가장 큰 %가 "하루에 몇 명까지 버틸지"를 정해요.

## 7. 체크리스트를 만들다 눈에 띈 것 (고치지 않았어요)

- 닉네임: 숫자를 3개 이하로 끊어 쓴 전화번호(`010 123 45`)는 통과해요.
- 처리방침 문의처가 `[문의 이메일]` 그대로예요.
- [머리맡 선물]의 겨울 선물 흐림 표시는 **기기 시계**(`new Date()`)로 정해요. 기기 날짜가 틀린 휴대폰에서는 서버와 다르게 보일 수 있어요(서버 검사는 맞게 해요).
- 차단을 풀 방법이 없어서, 실수로 막으면 30일 동안 풀 수 없어요.
- 게스트 토큰 서명의 마지막 글자는 바꿔도 받아들여질 때가 있어요(약 16번에 1번). base64url 43자의 마지막 글자에는 쓰지 않는 2비트가 있어서 `A`→`B`처럼 바꾸면 같은 바이트로 읽혀요. 서명을 위조할 수는 없어서 보안 구멍은 아니지만, 그래서 `tests/security.test.ts`의 "서명이 틀리거나 다른 비밀값이면 새 게스트로 봐요"가 가끔 실패해요.
